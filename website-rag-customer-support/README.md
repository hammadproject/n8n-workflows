# Website RAG Customer Support Chatbot

An n8n workflow that turns public website content into a Pinecone-backed knowledge base and uses a Google Gemini agent to answer customer questions from the indexed content. Firecrawl discovers pages, n8n cleans and chunks them, Gemini creates embeddings, and Pinecone provides semantic retrieval.

## Features

- Maps up to 100 website URLs with Firecrawl.
- Filters duplicate and unwanted paths.
- Processes pages sequentially with a two-second delay.
- Fetches HTML and converts it to readable text.
- Skips pages with insufficient content.
- Splits text into overlapping chunks for retrieval.
- Uses the same Gemini embedding connection for indexing and querying.
- Rebuilds a dedicated Pinecone namespace to prevent duplicate vectors.
- Provides a conversational support agent with short-term memory.
- Includes updated sticky notes covering every major stage.

## Architecture

```text
Ingestion branch
Manual Trigger
  -> Resolve Pinecone index host
  -> Clear dedicated namespace
  -> Firecrawl URL map
  -> Filter and deduplicate URLs
  -> Loop with rate-limit delay
  -> Fetch and clean HTML
  -> Validate and chunk text
  -> Gemini embeddings
  -> Pinecone

Chat branch
Chat Trigger
  -> Gemini customer-support agent
  -> Pinecone retrieval tool
  -> Grounded response to the user
```

## Requirements

- n8n Cloud or a self-hosted n8n instance.
- Firecrawl API access and the Firecrawl n8n community node.
- Google Gemini API access for the chat model and embeddings.
- A Pinecone account with a standard dense vector index.
- A publicly accessible website that you have permission to crawl.

## Configuration placeholders

| Placeholder | Where it appears | Replace with |
| --- | --- | --- |
| `https://example.com/` | **Map Website URLs** | The root URL of the website to index. |
| `YOUR_PINECONE_INDEX` | Pinecone vector-store and index-host nodes | Your Pinecone index name. |
| `YOUR_PINECONE_NAMESPACE` | Insert, retrieval, and namespace-reset nodes | A dedicated namespace for this website. |

## Pinecone preparation

Create a standard dense Pinecone index. Its vector dimension must match the Google Gemini embedding model selected in n8n. Use the same embedding model for both document ingestion and query retrieval; vectors generated by different embedding models are not compatible.

Use a dedicated namespace for this workflow. The ingestion branch intentionally deletes all vectors in the configured namespace before rebuilding it.

## Setup

1. Import [`workflow.json`](./workflow.json) into n8n.
2. Install the Firecrawl community node if it is not already available.
3. Connect your Firecrawl credential to **Map Website URLs**.
4. Connect your Pinecone credential to both vector-store nodes and the two Pinecone HTTP Request nodes.
5. Connect your Google Gemini credential to the chat-model and embedding nodes.
6. Replace `https://example.com/` with your website URL.
7. Replace every `YOUR_PINECONE_INDEX` and `YOUR_PINECONE_NAMESPACE` placeholder.
8. Confirm the Pinecone index dimension matches the selected Gemini embedding model.
9. Review the blocked URL keywords, crawl limit, request delay, minimum text length, chunk size, and overlap.
10. Run the ingestion branch and confirm vectors were created successfully.
11. Test the chat branch with questions whose answers appear on the website.
12. Customize the agent prompt, greeting, fallback message, and brand name before publishing.

## Default processing settings

| Setting | Default |
| --- | --- |
| Firecrawl URL limit | 100 |
| Request delay | 2 seconds |
| Minimum useful page text | 50 characters |
| Chunk size | Approximately 1,000 characters |
| Chunk overlap | Approximately 200 characters |
| Pinecone retrieval count | Top 10 chunks |
| Agent maximum iterations | 10 |

## Important deletion warning

The ingestion branch calls Pinecone's delete-vectors endpoint with `deleteAll: true` for `YOUR_PINECONE_NAMESPACE`. This prevents duplicate chunks on repeated crawls, but it permanently removes every existing vector in that namespace. Never reuse a namespace that contains data you need to preserve.

If automatic deletion is not appropriate, disable the two namespace-reset nodes and implement deterministic vector IDs or another update strategy.

## Customization

- Edit `blockedKeywords` to include or exclude website sections.
- Increase the crawl limit for larger sites.
- Adjust delay settings to respect the site's crawl policy and capacity.
- Change chunk size and overlap based on document structure.
- Tune Pinecone `topK` for retrieval breadth.
- Adapt the system prompt to the company's tone and escalation process.
- Add citations, ticket creation, lead capture, or human handoff tools.

## Security and responsible use

- Crawl only websites you own or are authorized to process.
- Review the target site's robots policy and applicable terms.
- Keep Firecrawl, Gemini, and Pinecone credentials outside version control.
- Do not index private pages, secrets, personal data, or restricted documents.
- Protect the published chat endpoint with appropriate rate limits and abuse controls.
